# 手册与文档组：排障知识沉淀为"任何人能读的纸面指南"

> 本组决策与可执行变更。素材来源：README.md、make_dist.py（FRIEND_GUIDE）、docs/acceptance_test/c_universal.md（普适性审计）、docs/ssh_expert/ssh_lead_spec.md（连接档案与 L0-L3）、docs/dataset_url_research/dataset_lead_spec.md（reason_code 与分级文案）、docs/ui_expert/ui_lead_spec.md，以及三机真机八条新失败案例（①-⑧ 活教材）。全中文、无 emoji、不写密码明文、零新框架；改动只触及文档与 make_dist.py 常量文本，不影响 pytest 88 基线与本仓代码行为。

## 决策

1. 手册按"阶段"组织，不按功能组织。非专家报障说不清组件名，只说得清"哪一步失败的"。docs/troubleshoot/GUIDE.md 的阶段轴与监控页 current_step 完全对齐（连接云端 → 克隆 → 环境 → 依赖 → 数据集 → 运行 → 结果收集 → 重跑），每条失败消息天然落在某阶段，查表零门槛。
2. 双入口单源：UI（b 组）每条建议动作只写"动作一句 + 锚点编号（如 G-3.3）"，步骤细节只在 GUIDE.md 维护一份；zip 内使用说明只放最常用 15 问与速查表，细节全部指向手册。杜绝同一排障步骤在 UI、使用说明、手册三处重复维护后失同步。
3. FRIEND_GUIDE 全文保留在 make_dist.py 常量内为单一事实源（打包自动生成 txt，并保持 txt 写入 zip 顶层这一 P0 修法），README 与 zip 说明都只放锚点级指引。
4. 服务器填写是全链路最大认知缺口（c_universal 审计结论），使用说明"服务器填写"一节用 AutoDL 三步开场——第一步就是"整行复制登录指令粘贴"，因为 AutoDL 随机端口与"ssh -p 端口 user@host"整行解析是本应用已支持的形态。
5. 八条真机案例不做"一次性修复记录"，而是全部改写为"症状→原因→动作"永久条目进速查表；其中密码内存态（⑦）与关窗断线程（⑧）属设计约束而非缺陷，放进"安全与成本提醒"前置告知，避免用户误判软件坏了。
6. 成本与安全只讲行为，不出现凭据：密码不落盘、关窗即断、云端按时计费这三条合为一段使用须知放在最前，而不是最后的小字。

## 可执行变更

### 1) FRIEND_GUIDE 增强（make_dist.py 常量改写为五章，每节逐字稿要点）

- 第一章 快速开始 5 步：① 解压，若系统拦截选"仍要运行"；② 装 Python 3.11+，勾选 Add python.exe to PATH；③ 双击 start_app.bat，首次自动建环境装依赖，约 1-5 分钟，失败自动换国内镜像；④ 浏览器自动打开 8505 即用；⑤ 页面打不开就等日志出现"已启动"再刷新一次。附一句：数据全在 C:\Users\<你>\.paper_repro_app，应用文件夹可随时删除换新版。
- 第二章 服务器填写（分两小节）：AutoDL 三步——控制台复制"SSH 登录指令"整行粘贴到服务器框（形如 ssh -p 端口 root@connect.xxx.seetacloud.com）→ 粘贴实例密码或点"注入公钥"→ 点"检测连接"，绿了再提交；换实例只改这一行。自有服务器——填 IP/域名、端口（默认 22）、用户名、私钥或密码，同样先检测后提交；填错时提示会指明卡在解析/可达/认证/环境哪一层。
- 第三章 常见问题 15 条 Q&A（每条一句话答案，锚点指向 GUIDE.md）：
  Q1 双击提示无 Python → 装 3.11+ 勾 PATH 重试。Q2 依赖安装失败 → 重试自动切镜像；仍失败手动 pip 加 -i 清华源。Q3 服务器连不上/信息正确却报不可达 → AutoDL 需粘贴整行登录指令并确认实例开机、端口为控制台最新值。Q4 认证失败 → 查密码、私钥公钥配对、注入公钥或到 AutoDL 控制台重置密码。Q5 连接成功但云端无 python/conda → 系统自动装 Miniconda（清华镜像），属正常等待，勿中断。Q6 训练报 Torch not compiled with CUDA → 曾装成 CPU 版，按 G-3.3 重装 CUDA 版（已默认禁 CPU 回退）。Q7 报 ModuleNotFoundError: ultralytics → 仓库依赖安装曾被容忍跳过，按 G-3.4 补装或重试。Q8 识别不到模型入口 → 仓库入口命名特殊（main/train/trainer/hubconf 差异），选"实际运行"手填命令。Q9 数据集下载失败 → 填镜像直链；MNIST 官方源 yann.lecun.com 国内不可达，系统已切 S3 源，一般无需操作。Q10 conda 环境 Python 版本与仓库不符 → 按 G-3.2 重建指定版本环境。Q11 重启后任务要密码 → 密码不落盘属安全设计，重新输入即可。Q12 关窗口后任务停了 → 线程随窗口结束属正常，重启应用后到历史记录重跑。Q13 换论文/换仓库会串数据吗 → 不会，每篇独立目录且哈希隔离。Q14 如何更新 → 删旧夹换新版，历史数据保留。Q15 页面打不开 → 刷新一次；端口被占会自动换，以页面地址为准。
- 第四章 排障速查表：表格列"症状 | 可能原因 | 动作"约 15 行，覆盖八条真机案例（无 python 自举、CPU 版 torch、requirements 被吞、入口识别 miss、MNIST 源不可达、conda 版本不符、密码重启失效、关窗断线程）与连接失败五类；动作列只写锚点。
- 第五章 安全与成本提醒：不把私钥、密码、登录指令发到公开聊天或仓库；云端按时计费，任务结束查看日志确认无残留进程再关机；关闭控制台窗口会中断任务线程，长任务期间保持窗口开启；重启后需重新输入密码。

### 2) README 补"遇到问题"一节

在第 5 节（一键启动）之后新增"6. 遇到问题"，正文约六行：先看 zip 内《使用说明》第三章常见问题；再按日志里的阶段标题查 docs/troubleshoot/GUIDE.md 四列速查表；错误首句是结论、次句是行动，把这两行连同阶段号带给别人即可求助；凭据内容请先打码。末尾链接 `docs/troubleshoot/GUIDE.md`。顺带把 README 的 Python 版本口径统一为 3.11+（与 pyproject/start_app 对齐，落实 c_universal P0 附带小修）。

### 3) docs/troubleshoot/GUIDE.md 结构（四列表：阶段 | 症状 | 原因 | 动作）

按章组织，每章内含一张四列表；动作列给锚点编号（G-章.行）并注明是否有 UI 一键入口，锚点全局唯一供 UI 引用。
- 第 0 章 读日志与总规则：阶段=current_step 标题行；错误首句结论次句行动；密码生命周期（仅内存、重启即失效）；窗口即线程。
- 第 1 章 本地启动：症状=双击无反应/提示无 Python/依赖装不上/白屏/端口被占；来源=README 与启动器现状 + c_universal 缺口。
- 第 2 章 服务器填写与连接：L0 解析、L1 可达、L2 认证、L3 环境预检四级，症状行直接复用 ssh_lead_spec 五类失败模板逐字稿（缺凭据/解析失败/不可达/认证失败/兼容受限）。
- 第 3 章 云端环境与依赖：案例① 无系统 python/conda 自举（Miniconda 清华镜像三级兜底）；② CPU 版 torch 崩溃与 CUDA 验证；③ requirements 失败被容忍吞掉 → 运行期 ModuleNotFoundError；⑥ conda 版本与仓库要求不符。
- 第 4 章 仓库与运行入口：案例④ main.py/train.py/trainer.py/hubconf 命名差异导致识别 miss；run 模式手填命令、超时与 ${PAPER_REPRO_DATA_CONFIG} 用法。
- 第 5 章 数据集：案例⑤ yann.lecun.com 不可达（torchvision 已切 S3）；镜像派生规则（ghfast.top/hf-mirror.com）；reason_code 枚举与 P0/P2/P4/P5 降级文案逐字稿；直链多候选与 2GB 上限（来源 dataset_lead_spec）。
- 第 6 章 运行中断与重跑：案例⑦ 密码重启失效（重输入口）；⑧ 关窗断线程与 GPU 残留检查；历史重跑回落单机直连的提示逻辑。
- 第 7 章 结果与指标：对比表"待填充"的论文指标注入入口；结果收集白名单四类文件；产物与图表路径。
内容源在文首引用本组报告：ssh_lead_spec（L0-L3、档案、五类模板）、dataset_lead_spec（reason_code、镜像、分级文案）、c_universal（P0-P2 缺口清单）、README/使用说明现状、八条真机案例。

### 4) 与 UI 帮助入口（b 组）的内容映射

约定：UI 所有 help、错误提示、建议动作统一携带锚点，格式固定为"动作一句（G-x.y）"，手册为唯一步骤源。映射表：服务器输入框 help（粘贴 ssh 登录指令/多候选）→ G-2.1 AutoDL 三步；"检测连接"四色胶囊各态 → G-2.2 至 G-2.5（对应五类失败模板）；数据集输入框 help 与降级结果卡"建议动作+复制直链" → G-5.1 至 G-5.4（镜像/多候选/2GB/degrade 原文）；CUDA 崩溃提示 → G-3.3；ModuleNotFoundError 提示 → G-3.4；环境诊断无 python/conda 提示 → G-3.1 自举；run 模式命令表单 help（入口命名差异表）→ G-4.1；监控页"重新执行"缺密码场景 → G-6.2（重输密码现场入口）与侧栏"启动窗口勿关"警示 → G-6.1；论文原文指标输入（高级选项）→ G-7.1；重启后首条"凭据需重输"提示 → G-0.3。实现约定：GUIDE.md 先行落地锚点，b 组 UI 文案全部改为"动作一句 + 锚点"，UI 内不展开多步骤，避免双份维护漂移。
