# 指标对比口径规范（专家组·指标对比口径研究员）

定位：本规范约束"与论文原文数值对比"的产生、计算与表述，防止把冒烟、减轮、异数据结果包装成"复现论文指标"。判据直接给结论，阈值集中为常量表，供选文组、执行组、验收组直接引用。涉及代码位置：comparison_table.py（表生成）、storage_utils.py（表组装与落库）、remote_runner.py collect 步骤（指标提取）、report_generator.py（报告模板）。

## 决策

### 1. 对比分级口径（三级，降级不可逆，报告必须标注级别）

- L1 全量复现（同配置同数据）：仓库固定到产出论文数值的 tag/commit（以 README 标称同版本为准）；训练数据、train/val 划分、验证集与论文一致；epochs、batch、imgsz、lr、EMA/amp 等与论文一致（单卡化调整必须登记进口径说明：总 batch 不变、GPU 数记为 1、评测协议一致）。只有 L1 允许写"复现指标与论文一致"，其差距作为达标判据。
- L2 同数据减轮（数据同论文，仅轮数减为 K）：标注 K/论文轮数，禁止用末值宣称匹配，必须给趋势外推结论：末 25% 轮次目标指标单调不减（允许一次回摆），按末段斜率外推至论文轮数的区间下界进入论文值±容差，才判"外推可一致"，数值标※。
- L3 同任务族样例集（冒烟，不宣称对比）：数据非论文数据（coco128 或任意子采样；train 样本比 r<2% 一律落 L3），只允许对比结构指标：loss 单调下降且较首值降≥30%、全程无 NaN、吞吐与官方单卡同量级（±50%）、权重产物完整。表内复现值列填"冒烟（不对比）"，并给数据规模折算说明："论文 N_train=…，本次 n_train=…，r=…%，数据差异主导指标差异，AP 不具可比性"。

### 2. 三篇选文定级（结合 a 选文，按规则回填）

判据主线只有一条：官方代码与数据集可达性 × 单卡 4090 全量时长 vs 训练窗口 W（W=任务预算−环境自举 3-6 分钟−10% 缓冲，即 10-25 分钟）。官方代码可达且全量训练 ≤W 的篇目定 L1；全量需 1-8 小时且官方数据可达的定 L2；官方数据为 COCO/ImageNet 级、专有采集数据或网络不可达的定 L3。组合约束：三篇必须覆盖 L1+L2+(L2 或 L3) 各至少一篇；若 a 组选文无 L1 候选，验收主结论自动降级为"流程跑通级（L2/L3）"，任何报告不得写"指标与论文一致"。回填登记表（选文组定稿后逐行填，缺行视为未定级）：

| 选文 | 定级 | 依据（官方数据可达性/全量预估时长 vs W） | 达标判据类别 |
| --- | --- | --- | --- |
| 篇一 | L1 | | L1 阈值 |
| 篇二 | L2 | | 外推可一致 |
| 篇三 | L2 或 L3 | | 外推/结构通过 |

### 3. 随机性处理

固定种子：仓库有默认种子则沿用（yolov5 与 ultralytics 默认 seed=0，即官方口径）；无默认时在命令尾追加 --seed 0（yolov5 风格）或 seed=0（ultralytics 风格），只经命令行传参，不改仓库代码，保持"原样复现"口径。多跑取均值：三台测试机同型（4090D），天然构成三次独立运行且不额外占时间——L1 篇目单次全量 ≤12 分钟时，三台各跑一个种子（0/1/2），合并报告均值±min/max 与论文报告口径对齐；单次训练接近预算上限则只跑单次，并注明"论文侧若为多 seed 均值±std，本单值落入其 ±std 带内即视为一致"。取舍结论：预算内优先"三机三种子一次成型"；任何情况不为凑均值牺牲全量轮数或压垮预算。

### 4. 对比报告结构

表列（与现 comparison_table 五列对应）：指标 | 论文值[出处] | 本机复现值 | 差距% | 口径说明。规则：

- 出处格式：论文 Table X / 仓库 README（release tag）/ 官方 benchmark，禁空、禁"网络流传值"；无官方数值的论文不入选（硬约束）。
- 示例行（非真实论文，仅示格式）：| mAP@.5:.95（COCO val2017） | 37.2 [README v6.2] | 36.4 | 0.8pp(2.2%) | L1；seed=0；单卡 batch 归一；三机均值 |。
- 差距%单元格内容为"绝对差（单位 pp）+ 相对%参考"，如"1.2pp(3.2%)"；主判据用绝对差，检测 mAP、分类 top-1、分割 mIoU 一律用 pp，相对百分比只作参考（AP 用相对百分比会夸大或缩小）。差值方向统一为"复现−论文"，loss 等越低越好指标取翻转符号，正=劣于论文。
- 口径说明登记：级别 L1/L2/L3、epochs K/Y、种子、batch 单卡归一、val 划分、单次或三机均值、外推标注。
- 报告证据三件套随表附上：训练日志尾 30 行与 [指标结果] 摘要行；复现命令全文（可回放，trace 已具备）；权重产物路径（best.pt/last.pt 等，远程路径列示并拉回本地 checkpoints/）。

### 5. 指标提取兜底规则（防误报成功）

优先级一：results.csv/metrics.csv/results.json/metrics.json（现 collect 已实现，CSV 取末行，token 过滤 map/precision/recall/f1/accuracy/acc/loss）。文件缺失时启用终端正则白名单，只抽"指标名+分隔符+数字"的锚定形态：mAP50-95 用 (mAP@0.5:0.95|map50-95|map)\s*[=:]\s*([0-9]*\.?[0-9]+)；mAP50 用 (mAP@0\.5|map50|map_0\.5)；P/R/F1 与 yolov5 列表行必须先验到列头行（含 P R mAP@.5 mAP@.5:.95）才抽取；acc/top1/loss 同锚。防误报四道校验：时间线校验（指标行时间戳须晚于首个 epoch 起始行，滤掉下载/环境噪声）；单位域校验（acc/mAP 属 [0,1] 或 [0,100]，超域丢弃；loss 必须为正）；sanity 校验（全零/NaN/Inf 置 flag 不采信）；冲突取舍（同指标多来源取最后验证阶段值，来源记"文件:行号"或"log:行号"）。全无命中时报告写"未提取到指标（训练未发生或未输出）"，禁止以 exit 0 冒称成功：run 之后须校验日志确含 epoch 推进或 step loss 输出，否则判"训练未发生"并走失败分支。

### 6. 验收通过判据（数值级结论）

流程通过：status=success，确有训练输出（L1 全量轮数、L2 K 轮），权重产物存在。指标可接受（L1 达标阈值，均为绝对差）：分类 top-1 ≤3pp（对常见 70-95% 准确率约合相对 3-4%）且末 20% 轮次改善 <0.1pp/轮（收敛）；检测 mAP@.5:.95 ≤2.5pp、mAP@.5 ≤3pp（同实现多 seed 方差约 0.3-0.8pp，跨实现容差取 2-3pp）；分割 mIoU ≤3pp。loss 只作趋势不作达标单判据。L2 只判"外推可一致"，L3 只判结构通过；未收敛（末 20% 轮次仍快速改善）一律不判"达成"。

## 可执行变更

1. comparison_table.py：删除 default_rows 的 N/A 占位默认行（现实现会在无数据时伪造 Top-1/mAP/F1/速度对比行，属最大误导源）；行结构扩为 metric、paper_value+出处、level、repro、gap_pp、caliber；论文基准未录入时整表替换为一行声明"论文基准未录入，本次未做指标对比"，不输出伪行。
2. 新增论文基准数据文件 paper_claims.json（每篇一份，选文组一次录入），字段：metric、paper_value、unit、source（表号/README tag）、direction（越高越好/越低越好）、seed_std、paper_caliber{dataset,epochs,batch,gpus,seed,imgsz,val}；storage_utils 组装表前做非空与 direction 校验。
3. collect 兜底落地：将第 5 节白名单正则与四道校验写入 .collect_results.py 脚本；来源支持 log:行号伪来源；结果 payload 增 verdict 字段与 sanity flags。
4. L2 减轮支持：auto 模式对判定超预算的仓库自动追加 --epochs K（K=floor(W/实测单轮秒×0.9)），日志首行打 REDUCED_EPOCHS=K/FULL=论文轮数，供报告自动标注 K/Y。
5. report_generator.py：在"主要风险"与"结论"之间插入"指标对比与复现口径"节，占位渲染：分级结论行（L1 达标/L2 外推一致/L3 冒烟/不达标）、对比表、日志摘要、复现命令、产物路径、L3 数据规模折算说明。
6. 判定阈值集中为常量表（3pp/2.5pp/3pp/0.1pp 每轮），由 storage_utils 后处理调用 compute_verdict(claims, metrics, meta) 写回 result，UI 成功卡显示级别徽章。
7. 产物回传：collect 已列的 best.pt/last.pt 等由收尾步骤拉回本地 checkpoints/{task_id}/，并在 manifest 登记路径，保证"权重产物路径"证据可复核。
