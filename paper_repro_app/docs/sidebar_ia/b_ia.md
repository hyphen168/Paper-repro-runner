# 侧栏信息架构 · 专家组裁决稿（b_ia）

根因一句话：新功能全部"折叠 + 条件渲染 + 无折叠态自述"，侧栏首屏只剩两个叠着的内容块与三个装饰性小节，"入口"在视觉上不存在。裁决目标：折叠也自描述、模式永不隐身、引导一次即安静。基线约束：104 测试全绿、AppTest 0 异常、零新框架、无 emoji、口令门与表单空白语义不动、不落明文凭据。

## 决策

### 1. 终版五组与顺序

自上而下固定：**A 云服务器与任务 → B 智能助手 → C 手机与远程 → D 环境与氛围 → E 帮助与手册**。

排序依据：使用频次 × 设置依赖。A/B 是"配一次、反复用"的功能主群且与主区任务流同频（A 供提交前确认云端去向、B 供失败时求助）；C 是按需通道——必须看得见；D 纯装饰最低频；E 兜底。现代码把「遇到问题？先看这里」放在侧栏最顶（折叠态），正是"看着像没有内容"的头号来源，整体下移为 E。

旧块映射：FAQ expander → E；「AI 助手（失败自动调试）」→ B；「手机直达与受信设备」expander（现仅 `PAPER_REPRO_EXPOSE in (lan,tunnel)` 渲染）→ C 并**去条件常驻**；「云端配置」信息块拆解——配置目录 + 当前任务行归 A，本机/局域网访问地址行归 C 头行（标题"云端配置"实为访问信息，名实不符，趁机纠正）；「当地定位与天气」+「背景天气预览」两段合并为 D 单组；「仓库档案管理」（现历史记录 tab 底部）上移入 A 组单实现。

### 2. 每组展开默认策略（只首帧生效，之后交还用户）

Streamlit expander 无 key 时开合态按会话记忆；故"默认"只在首帧出现一次，不影响用户后续自由开合——这正是要的"引导一次即安静"。

| 组 | 首帧默认 | 理由/权衡 |
|---|---|---|
| A | 引导态（会话首帧且历史无 success 任务）True，否则 False | 首次把建档空白与"云端只执行"讲清楚；常态收成标题行防侧栏过长 |
| B | 未配置 True；已配置 False | 把"待办配置"推到眼前；配完自动收起 |
| C | 桌面模式 True；远程模式 False | 桌面体仅 3 行指引，矮；远程体含直达地址+受信列表，重，常开顶掉首屏 |
| D / E | False | 装饰与兜底，靠自描述标题即可 |

权衡结论：常态（配置完毕后）全侧栏仅 5 条自述标题 + 至多 1 组展开，约 200px 不滚屏；最坏情况 = 引导首帧 A+B+C 三段，约占 2/3 屏高，仅出现一次，可接受。CSS 已有 `details + details { margin-top: 12px }` 保证间距，无需新样式。

### 3. "手机与远程"常驻设计（模式永不隐身、文案不撒谎）

原则：桌面模式**不展示**"手机功能列表"，只展示"怎么开启"，杜绝误导；远程模式切为管理体。

- **桌面模式**（expose 空）：徽章行灰点「远程未开启 · 桌面本机」；组体 = 指引卡三行：① 需手机/平板访问时，关闭本窗口后双击 `start_app_remote.bat` 启动（局域网、同 WiFi 可用，启动脚本会提示防火墙放行）；② 公网反隧（tunnel）用 `.venv\Scripts\python start_app.py --expose tunnel` 启动后经 SSH 反隧回环进入，细节指向 E 组手册；③ 启用后首访先设一次访问口令，再回到本组管理直达地址与受信设备。附 `st.code("start_app_remote.bat")` 供复制。**不放无动作的假按钮**。
- **远程模式**（lan/tunnel）：徽章行绿点「远程已启用 · 局域网 / 反隧」+ 直达地址 code（复用现有 IP 探测逻辑，唯一事实源）；组体 = 受信设备管理，现有 `gate_list()` 列表 / 吊销 / 吊销全部**原样平移**，key（`tk_revoke_*`）不变。口令设置仍只在口令门首访完成，本组不放口令框（避免"这里改口令"的误解）。安全语义零变化。

### 4. AI 助手入口强化

Streamlit expander 标题不支持富文本，故用 expander 上方的**徽章行**承载状态（折叠时仍可见），复用 `.status-dot` 风格内联圆点，无新 CSS、无 emoji：

- 未配置：灰点（#5c6f96）+「智能助手 · 未配置：任务失败可一键 AI 分析根因，配置一次即解锁」；expander 标题「立即配置（约 1 分钟）」。
- 已配置：绿点（#00ffa3）+「智能助手 · 就绪：模型名（截 24 字）· 思考 = 标准/深度/快速」；标题「修改设置与测试」。

折叠默认策略：`expander(key="sb_ai_exp")`，首帧若未配置预置 True、已配置预置 False（先写 session_state 再建控件，避免切换竞态）；保存成功 `st.toast("AI 助手已就绪")` 并把 key 置 False 自动收起，保持常态侧栏短。已配置后失败诊断卡的「AI 分析失败原因」按钮照旧，作为第二入口。

### 5. 空态与发现（一次性提示，不重复）

机制：`_one_shot(key)` 帮助函数，session_state 布尔（沿用现有 `dn_boot`/`dn_rise_done` 先例），只存内存、不落盘、无凭据；提示渲染在主区对应上下文顶部，**不入侧栏**。同一提示每会话至多一次。三条文案（示例，无 emoji）：

1. 手机（桌面模式会话首帧，主区顶部 st.info）：「手机控制已上线但默认关闭：当前为桌面本机模式。需要手机/平板查看监控时，退出后用 start_app_remote.bat 启动，侧栏会出现直达地址与受信设备管理。」
2. AI（首次出现任务失败且未配置，失败卡顶部一次）：「新功能：失败任务可一键 AI 分析根因（发送前自动脱敏）。在侧栏「智能助手」填服务商、模型与 API Key 并测试保存即可解锁；未配置时本卡始终保留此入口。」
3. 档案（提交页首次出现「填入上次成功配置」按钮时一次）：「仓库档案已启用：同一仓库第二次提交会自动记住上次成功命令与数据集，故出现此按钮；历史记录的档案管理区可查看或删除记忆。」

### 6. 护栏

（1）`_access_gate()` 仍最先执行，直通/受信 token 判定顺序不动；（2）表单空白默认、密码框 type=password、凭据只走 ai_config DPAPI 与进程内存，全部不动；（3）新控件 key 一律 `sb_` 前缀；被重排的旧控件补显式 key 防隐式 id 漂移；（4）档案/受信管理单实现，删旧留新；（5）无 emoji，①②③ 圈号沿用现文案先例。
